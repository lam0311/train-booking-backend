Tiêu Chuẩn Bảo Mật OWASP & Phòng Thủ Đa Lớp

Triển khai các cơ chế bảo mật theo tiêu chuẩn OWASP: bảo vệ HTTP headers với Helmet, giới hạn tần suất yêu cầu chống brute-force/DDoS, mã hóa mật khẩu an toàn với Bcrypt, quản lý phiên làm việc bằng Token kép (Access/Refresh Token) và kiểm tra mã nguồn tĩnh.

01. GIỚI HẠN TẦN SUẤT YÊU CẦU (RATE LIMITING) EXPRESS-RATE-LIMIT

Giới hạn số lượng yêu cầu theo từng địa chỉ IP. Ngăn chặn bot spam đặt vé tự động và giảm thiểu nguy cơ tấn công từ chối dịch vụ (DDoS).

[PASS] A01: Broken Access Control IDOR & AUTHZ
Kiểu lỗ hổng: Người dùng truy cập, xem hoặc sửa/xóa trái phép dữ liệu của người khác (IDOR, leo thang đặc quyền ngang/dọc).
Phòng vệ: Mọi endpoint thao tác vé đều đối soát quyền sở hữu req.auth.userId === allocation.userId.
[PASS] A02: Cryptographic Failures CRYPTO & LEAK
Kiểu lỗ hổng: Dùng thuật toán băm yếu (MD5/SHA1), lưu mật khẩu dạng thô, hoặc hardcode Secret Key vào mã nguồn gây lộ lọt.
Phòng vệ: Mật khẩu băm Bcrypt 12 Salt Rounds (~400ms/hash chống GPU crack); Secret tách biệt qua biến môi trường .env.
[PASS] A03: Injection Attacks NOSQL & QUERY
Kiểu lỗ hổng: Chèn toán tử truy vấn độc hại ($ne, $gt, script) vào JSON request nhằm vượt qua xác thực hoặc trích xuất dữ liệu DB.
Phòng vệ: Zod Schema ép kiểu nghiêm ngặt và lọc sạch input trước khi vào Controller; Mongoose ODM tham số hóa toàn bộ query.
[PASS] A04: Insecure Design RACE & REPLAY
Kiểu lỗ hổng: Khiếm khuyết kiến trúc: người dùng spam click gây trừ tiền/đặt vé 2 lần, hoặc 2 người cùng tranh chấp mua 1 ghế cùng thời điểm.
Phòng vệ: Header Idempotency-Key + SHA-256 chống lặp vé; giải thuật Bitmask nguyên tử $bitsAllClear triệt tiêu Race Condition.
[PASS] A05: Security Misconfiguration HEADERS & CORS
Kiểu lỗ hổng: Lộ thông tin framework (X-Powered-By: Express), thiếu HTTP Security Headers (dễ bị Clickjacking), hoặc mở CORS tự do cho mọi domain.
Phòng vệ: Middleware Helmet tự động thiết lập HSTS, X-Frame-Options, ẩn header nhạy cảm; CORS cấu hình whitelist chặt chẽ.
[PASS] A06: Vulnerable Components SCA & NPM CVE
Kiểu lỗ hổng: Sử dụng các gói thư viện bên thứ 3 (NPM packages) đã lỗi thời, chứa mã độc hoặc có lỗ hổng CVE công khai chưa vá.
Phòng vệ: Rà soát tự động qua công cụ SCA npm audit --omit=dev; 100% các dependency trong runtime đạt chuẩn an toàn 0 CVE.
[PASS] A07: Identification & Auth Failures BRUTE FORCE & JWT
Kiểu lỗ hổng: Cho phép hacker gửi hàng triệu request dò mật khẩu (Brute Force/Credential Stuffing) hoặc token không thể vô hiệu hóa khi bị lộ.
Phòng vệ: Rate Limit 20 req/phút chặn đứng brute-force; cơ chế Dual Token (Access Token 15 phút, Refresh Token xóa khỏi DB khi logout).
[PASS] A08: Software & Data Integrity DESERIALIZE & TAMPER
Kiểu lỗ hổng: Deserialize dữ liệu không an toàn (RCE qua object injection), sửa đổi payload giao dịch trên đường truyền, hoặc dùng hàm eval().
Phòng vệ: Mã nguồn nói KHÔNG với eval(); kiểm soát toàn vẹn JSON bằng Zod và chữ ký số SHA-256 cho mỗi giao dịch.
[PASS] A09: Security Logging & Monitoring LOGGING & PROBES
Kiểu lỗ hổng: Không phát hiện được xâm nhập do thiếu log, hoặc ghi đè mật khẩu vào log; để lộ chi tiết lỗi kỹ thuật và cấu trúc server cho client.
Phòng vệ: Middleware xử lý lỗi tập trung chuẩn hóa ErrorResponse (giấu hoàn toàn stack trace); 2 probes thời gian thực /health/live và /health/ready.
[PASS] A10: Server-Side Request Forgery SSRF & WEBHOOK
Kiểu lỗ hổng: Server nhận URL từ phía người dùng rồi tự động gửi request đến URL đó, khiến mạng nội bộ hoặc cloud metadata bị lộ.
Phòng vệ: Hệ thống backend được đóng gói thuần túy, không cung cấp bất kỳ API nào nhận URL ngoài từ client; miễn nhiễm 100% với SSRF.
[PASS] Extra: Thundering Herd / Cache Stampede CONCURRENCY & DB CRASH
Kiểu lỗ hổng: Hàng ngàn request ập vào cùng lúc đúng thời điểm Cache rớt/hết hạn khiến toàn bộ query dồn vào DB, gây sập database tức thì.
Phòng vệ: Áp dụng kỹ thuật Request Coalescing qua inFlightLoads Promise Map: chỉ 1 request tải từ DB, các request đồng thời khác chia sẻ chung kết quả.

TẦNG 04: DOMAIN LAYER (NGHIỆP VỤ CỐT LÕI // CORE)

TẦNG LOGIC CỐT LÕI (CORE DOMAIN)
VAI TRÒ TRÁCH NHIỆM CHÍNH:

Trung tâm xử lý logic nghiệp vụ cốt lõi. Chuyển đổi bài toán phân bổ ghế liên trạm thành các phép toán thao tác bit nhị phân. Tầng này được thiết kế thuần khiết (Pure Functions, không phụ thuộc thư viện ngoài), cho phép kiểm tra trùng chặng tức thì.

CÔ LẬP // PHỤ THUỘC (DIP):

Độc lập tuyệt đối! Không phụ thuộc vào bất kỳ tầng nào khác (Zero Outward Dependencies).

QUY TẮC BẤT BIẾN (INVARIANTS):

4 phân đoạn hành trình nằm gọn trong 4 bit (0–15). Không tồn tại bitmask âm hoặc > 15.

INPUT: fromIndex (0..3), toIndex (1..4), occupiedMask (0..15).
OUTPUT: segmentMask (0..15), clearMask (0..15), hasConflict (boolean).
TỆP TIN:
src/modules/bookings/domain/segment-mask.js
src/modules/bookings/domain/segment-mask.js JavaScript 
const TOTAL_SEGMENTS = 4;
const FULL_MASK = 15;

const buildSegmentMask = (fromIndex, toIndex) => {
    const segmentCount = toIndex - fromIndex;
    return ((1 << segmentCount) - 1) << fromIndex;
};

const hasConflict = (mask1, mask2) => {
    return (mask1 & mask2) !== 0;
};

const buildClearMask = (segmentMask) => {
    return FULL_MASK ^ segmentMask;
};

module.exports = { buildSegmentMask, hasConflict, buildClearMask };

ĐỀ XUẤT 01 // THUẬT TOÁN

Mở Rộng Tuyến Tàu Dài (Dynamic Bitmask)

Hiện tại hệ thống đang mô phỏng tuyến 5 ga cố định. Nhóm tiếp theo có thể mở rộng lên toàn tuyến thực tế từ 20 đến 30 ga (như tuyến Hà Nội - Sài Gòn).

Cách triển khai: Sử dụng kiểu dữ liệu BigInt có sẵn của JavaScript (1n << n) thay cho số nguyên 32-bit. Logic thuật toán Bitmask vẫn giữ nguyên và tốc độ kiểm tra trùng chặng vẫn tức thì.

ĐỀ XUẤT 02 // TRẢI NGHIỆM NGƯỜI DÙNG

Giữ Chỗ Tạm Thời Khi Thanh Toán (Holding 10 Phút)

Khi người dùng chọn ghế, hệ thống tạm giữ ghế trong 10 phút để khách nhập thông tin và thanh toán. Nếu quá 10 phút chưa thanh toán thì tự động nhả ghế lại.

Cách triển khai: Lưu thông tin ghế đang giữ vào Redis kèm thời gian hết hạn (TTL = 10 phút). Khi hết giờ Redis sẽ tự xóa khóa, giải phóng ghế mà không cần viết cron job phức tạp.

ĐỀ XUẤT 03 // GIAO DIỆN & TƯƠNG TÁC

Cập Nhật Ghế Thời Gian Thực (WebSocket / SSE)

Khi có ai đó đặt ghế thành công, sơ đồ ghế trên màn hình của tất cả những người khác đang cùng xem chuyến tàu sẽ tự động đổi màu mà không cần bấm F5.

Cách triển khai: Dùng Server-Sent Events (SSE) hoặc thư viện Socket.io. Server phát sự kiện khi có vé mới, trình duyệt nhận tín hiệu và cập nhật trực tiếp màu ghế trên giao diện.

ĐỀ XUẤT 05 // ĐỘ ỔN ĐỊNH

Bộ Nhớ Đệm Dự Phòng (Local Cache Fallback)

Giúp ứng dụng vẫn hiển thị được lịch trình chuyến tàu và thông tin ghế cho người dùng xem ngay cả khi Redis gặp sự cố hoặc máy chủ bị mất mạng tạm thời.

Cách triển khai: Lưu sẵn bản sao dữ liệu chuyến tàu vào bộ nhớ RAM máy chủ (sử dụng Map hoặc thư viện node-cache). Nếu không kết nối được Redis, hệ thống tự động lấy từ RAM ra hiển thị.
