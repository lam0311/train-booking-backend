TẦNG 04: DOMAIN LAYER (NGHIỆP VỤ CỐT LÕI // CORE)

DOMAIN HEART (O(1))
VAI TRÒ TRÁCH NHIỆM CHÍNH:

Trái tim bất biến của phần mềm (The Core Heart). Chuyển bài toán phân bổ ghế liên trạm thành các phép toán đại số Boolean trên thanh ghi ALU. Tầng này thuần khiết (Pure Functions, Zero External Dependencies), kiểm tra trùng chặng trong đúng 1 chu kỳ xung nhịp CPU O(1).

CÔ LẬP // PHỤ THUỘC (DIP):

Độc lập tuyệt đối! Không phụ thuộc vào bất kỳ tầng nào khác (Zero Outward Dependencies).

QUY TẮC BẤT BIẾN (INVARIANTS):

4 phân đoạn hành trình nằm gọn trong 4 bit (0–15). Không tồn tại bitmask âm hoặc > 15.

INPUT: fromIndex (0..3), toIndex (1..4), occupiedMask (0..15).
OUTPUT: segmentMask (0..15), clearMask (0..15), hasConflict (boolean).
TỆP TIN:
src/modules/bookings/domain/segment-mask.js
src/modules/bookings/domain/segment-mask.js JavaScript 
const TOTAL_SEGMENTS = 4;
const FULL_MASK = 15;

const buildSegmentMask = (fromIndex, toIndex) => {
    const segmentCount = toIndex - fromIndex;
    return ((1 << segmentCount) - 1) << fromIndex;
};

const hasConflict = (mask1, mask2) => {
    return (mask1 & mask2) !== 0;
};

const buildClearMask = (segmentMask) => {
    return FULL_MASK ^ segmentMask;
};

module.exports = { buildSegmentMask, hasConflict, buildClearMask };

ĐỀ XUẤT 01 // CẤU TRÚC DỮ LIỆU & THUẬT TOÁN

Scale Về Mặt Thuật Toán

Nâng cấp thuật toán Bitmask từ 4 chặng tĩnh sang Dynamic Bitmask/BigInt để hỗ trợ các tuyến thực tế dài 30-50 ga.

Giải pháp triển khai: Mở rộng không gian số nguyên sang kiểu dữ liệu BigInt (hỗ trợ độ dài bit tùy ý) hoặc tích hợp thư viện nén Roaring Bitmaps để quản lý toàn bộ tuyến đường sắt dài hàng chục ga mà vẫn duy trì độ phức tạp tính toán O(1) cho các phép toán AND, OR, XOR bitwise.
ĐỘ ƯU TIÊN: MỞ RỘNG TOÀN TUYẾN BẮC - NAM
ĐỀ XUẤT 02 // HIỆU NĂNG & CONCURRENCY

Scale Về Mặt Chịu Tải

Triển khai cơ chế giữ chỗ tạm thời (Holding TTL) và dùng Redis Lua Script/Message Queue để giải quyết triệt để nút thắt cổ chai ở Database khi có hàng chục nghìn người tranh chấp cùng lúc.

Giải pháp triển khai: Quản lý trạng thái khóa ghế tạm thời (Pending Lock) bằng Redis với thời gian hết hạn TTL (ví dụ 10 phút thanh toán). Sử dụng Redis Lua Script để atomic hóa việc kiểm tra - giữ chỗ, kết hợp Message Queue (Kafka / RabbitMQ) đẩy các tác vụ ghi vào hàng đợi bất đồng bộ nhằm loại bỏ hoàn toàn hiện tượng nghẽn I/O tại Database.
